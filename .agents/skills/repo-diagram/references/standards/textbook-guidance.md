# Textbook guidance — informative, not normative

These books guide selection and communication style; they do not override OMG/ISO
normative semantics.

## UML

Martin Fowler — UML Distilled, 3rd ed.
Use as the practical filter: prefer the smallest UML subset that communicates the
design clearly instead of dumping the full metamodel.

Grady Booch, James Rumbaugh, Ivar Jacobson — The Unified Modeling Language User Guide,
2nd ed.
Use as a modelling-practice reference for software-intensive systems.

When practical-book guidance conflicts with OMG UML 2.5.1 semantics, OMG wins in
textbook-strict mode.

## Architecture

Simon Brown — Software Architecture for Developers.
Use for pragmatic C4 modelling and architecture communication.

Len Bass, Paul Clements, Rick Kazman — Software Architecture in Practice, 4th ed.
Use to keep views tied to stakeholder concerns and architecturally significant
quality attributes rather than overloading one picture.

## Databases

Silberschatz, Korth, Sudarshan — Database System Concepts, 7th ed.
Use Chapter 6 for entities, relationships, mapping cardinality, participation,
weak entities, and generalization/specialization.

James Martin / Information Engineering.
Use as the practical lineage for Crow's Foot-style logical/physical ER presentation.

Books are informative guidance. Mechanical checks are documented in the
standard-specific files and validator.
